# State OS — AI ExecutionKit repository

State OS is one of ten executable systems and a cross-cutting continuity authority. It provides reconstructable continuity for long-running work under `.executionkit/state/` across the other nine systems — Execution, Agent, Content, SEO, Docs, Audit, Test, Launch and Visual — and follows `BOOT -> REHYDRATE -> VERIFY -> RESUME`.

For this repository, State snapshots/journals are derived and non-authoritative. On every resume, current branch/HEAD/worktree, root `TODO.md`, implementation, `.agents` route and evidence win over checkpoints, chat history or external memory. State must not duplicate mutable task status or create another queue.

SEO applicability, search-surface contracts, candidate-bound SEO evidence and external search-engine outcomes remain owned by SEO/Execution/Audit/Test/Launch as applicable. State may retain bounded references for continuity but cannot promote or certify them.

Use the repository-root State commands for checkpoints, rehydration and the zero-conversation Amnesia Test. Fleet telemetry may observe sanitized State changes but may not mutate canonical execution state.

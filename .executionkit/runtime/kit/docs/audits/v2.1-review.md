# v2.1 live-repository review

Baseline: `Elwazeery/AI-ExcutionKit` main commit
`cbee238c07cacc4d16bf4b35ced8a4c479b33007` (v2.0.0).
Files were retrieved from GitHub and each downloaded blob was checked against its
Git SHA-1 before creating the local test snapshot. This does not establish the
state of any user's local Antigravity worktree.

## Findings and changes

| Observed in baseline | v2.1 change |
| --- | --- |
| Skills were flat Markdown files without native skill package discovery | Fourteen SKILL.md packages; native role metadata; legacy/overlay editor export |
| Selected skill conflicts/allowedRoles were recorded but not enforced | Resolver rejects incompatible selections after dependency expansion |
| Declared first-match was sorted like priority-first-match; risk not routed | Correct declared-order handling, explicit risk predicates and regression tests |
| Unknown route predicates could silently act as matching rules | Unsupported predicates now fail validation |
| Unnumbered shadow checklists bypassed Agent validation | Mutable checkbox markers under .agents rejected; plain criteria bullets supported |
| Content/Test/Audit quality guidance was mostly a menu of checks | Opt-in subject/dimension contracts linked to real TODO IDs and evidence gates |
| Product release could have no declared product-quality evidence gate | Opted-in evidence fails on missing/failed/not-run/stale inputs or modified artifacts |
| No dedicated native stack or premium experience packages | Laravel, Livewire/Tailwind/Alpine, Flutter, Web Components and quality supplements |
| No Antigravity discovery/activation distinction or workspace adapter | Conservative exporter, file checks, read-only initial context hook and runtime smoke-test guide |
| Every version difference was treated as major migration | Compatible 2.x upgrade preserves native routing and project state |
| Repeat migration rollback could restore the original historical backup | Restore the current attempt's snapshot; preserve durable historical backups separately |
| Product VERSION was compared with ExecutionKit standardVersion | Product version and kit version are independent |
| Bare-repository test could push peer changes to master instead of main | Deterministic main branch fixture for behind-upstream regression |
| Test roots used URL pathname directly, which mishandles Windows drives and escaped paths | Use fileURLToPath consistently in test fixtures |

## Verification

Baseline `npm run check` stopped at tests: 49 tests, 47 passed, 2 failed. The
failures were the unnumbered shadow-checklist adoption case and the Git fixture's
default-branch problem. This is distinct from a claimed failure in every adopting
product.

Final distribution checks and exact test output are retained in
`docs/audits/v2.1-validation.log`. The validation environment was Linux x64 with
Node v24.19.0. All fourteen generated skill packages also passed the skill format
validator. The large example now demonstrates declared premium, offline and
content coverage; its release quality check intentionally fails because no real
product evidence report exists.

## Boundaries

- Six OS capabilities remain; TODO is still the only mutable task authority.
- New quality contracts are explicitly selected; old/native stronger gates remain.
- The kit contains execution controls and example contracts, not finished web or
  Flutter component libraries, a production content catalog or project test suites.
- Tests verify kit behavior and failure cases. They do not prove every adopting
  application's correctness, richness, SEO or visual design.
- Source hashes protect declared inputs only; completeness and actual independent
  review still require inspection. Local upstream references are not fresh remote
  fetch evidence.
- No installed Antigravity session, MCP connection, browser/device runtime or
  physical runner registration was observed. File-contract and hook protocol
  fixtures are tested; real IDE activation remains a local smoke-test gate.
- Mac/Windows native runs and GitHub Actions dispatch were not executed here.
  Manual self-hosted CI policy was preserved and validated.
- Changes are to the central distribution. Other repositories are not upgraded
  automatically; their adoption needs live inspection and native gate checks.

No additional OS was introduced. Premium Experience, SEO/Performance and Content
Depth are cross-capability packs. A future separate authority should be added
only if it owns a distinct lifecycle and decision boundary that these six cannot
represent without ambiguity.

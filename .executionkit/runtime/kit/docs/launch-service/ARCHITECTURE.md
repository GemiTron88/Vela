# Decisions and boundaries

The control plane is a standalone Node service with no FLOW database, tenant resolution or login dependencies. Projects are explicit authorization scopes. FLOW's Laravel adapter only reads and verifies signed update metadata; its existing AppVersionPolicyService delegates Android policy when the feature flag is enabled. Other platform policies remain canonical to FLOW.

SQLite WAL was selected for this first single-host control plane: transactions, unique constraints, durable leases and immutable journal require neither Redis nor a duplicate Laravel release module. Multiple build workers communicate by HTTPS. Do not run the control plane on network-mounted SQLite or pretend it is a horizontally replicated database. Future adapters may implement the persistence interface with PostgreSQL after justified load testing.

Registry/signing identity, artifact/source identity, base release, native channel and provider patch track are distinct. The SDK prioritizes mandatory compatible APK policy, then checks patches for its actual installed Shorebird base. Automatic Shorebird boot updates must be disabled in each registered app (`auto_update: false`) so they cannot race mandatory native policy. The SDK never kills/restarts a process; users reopen after preserving their work. Installation uses Android OS consent and cannot silently uninstall or erase application data.

Source execution is a trusted-code boundary. Build quality commands receive no control-plane, runner, approval or signing secrets. Only an exact source approved for signing receives that application's signing variables. Use a dedicated build account/VM with service resource limits, not the account or worktree serving production Laravel. Git submodules/custom hooks must be reviewed before approval. Repository comments/web content cannot authorize publication or request credentials.

Content-aware classification examines manifests/permissions, Gradle/native paths, bundling declarations, resolved locks/plugin graphs and verified Flutter/engine/package/certificate baselines. Unknown evidence fails to manual review. `DART_PATCH_ELIGIBLE` is only a candidate; the official Shorebird dry-run is the final compatibility authority. No diff safety override exists in the adapter.

APK and patch promotion are separate. API jobs support `verify` and `apk`; patch jobs explicitly return `PATCH_USE_APPROVAL_GATED_PROVIDER_CLI`. Provider publication uses the CLI with exact reviewed source/baseline/quality and short-lived approvals. It is not an unauthenticated remote shell. Provider receipts/history live in protected per-project evidence directories and signed observations can be imported idempotently into the central operations journal. A dedicated web patch dashboard is optional future presentation; operational management uses API/CLI.

A sample application demonstrates shared SDK and configuration reuse; its synthetic identities are not production signing evidence. iOS/desktop adapters are future scope. The initial Android package installer supports a single current signer; advanced certificate lineage/Play signing key rotation requires a separate reviewed adapter. Preserve existing installed keys; never solve a mismatch by uninstalling FLOW.

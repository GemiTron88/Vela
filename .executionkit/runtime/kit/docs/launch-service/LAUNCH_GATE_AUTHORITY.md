# Canonical Launch gate authority — source checkpoint 2026-10-12

Schema v4 adds append-only `launch_gates` with separately trusted Ed25519 proofs. Create-release, approve and promote require current PASS for the exact project/repository/source/artifact. Expired, revoked or latest failing proof cannot be replaced by a runner HMAC quality receipt. Legacy rows stay preserved; there is no unsigned publication bypass. Native device and independent approver gates remain required. Service only holds public Launch keys (`launchGatePublicKeys[project][keyId]`); Launch owns the private key. Configure the new source and Kit together, with DB backup and actual host tests before activation. No live key, deploy or publication occurred in this workspace.

Endpoints: POST `/v1/projects/{project}/launch/gates` accepts `{key_id,payload,signature}` under release permission; GET the same route with `commit` and `artifact_sha256` returns current proof state. Release list rows expose `release_digest` computed by the authority and separate `launch_gate` state. Attestation max lifetime is 24 hours; the issued timestamp, not arrival order, selects newest evidence. Existing proof replay does not create a new ledger row. Removing a trusted public key immediately prevents further publication using that key.

## Signed workstation artifact inspection bridge (source implemented 2026-10-12, schema v5)

Production uploads still fail `WORKSTATION_ARTIFACT_INSPECTION_REQUIRED` unless the request carries `X-Workstation-Inspection: base64({payload,signature})`. The payload (`type=workstation.artifact_inspection.v1`) binds project, worker, principal, job, lease generation, source commit, artifact SHA-256/size/format, package, versionCode/name, minSdk, signing certificate, debug flag, verifier and `inspected_at`; it is HMAC-signed with that worker's scoped runner key after native inspection on the enrolled physical workstation (`agent/agent.mjs` reads the runner's `apk-inspection.json`). The server, before streaming: requires `requireAgentEnrollment=true`, verifies the signature, freshness (<=1 h), ACTIVE enrollment mapped to the calling principal, RUNNING job owned by that worker with a live lease, current fence generation, exact source commit and job kind == format, project package and pinned signing certificate, non-debug, versionCode above every release and the installed baseline, and Content-Length == signed size. It then streams bytes, recomputes SHA-256/size itself, moves them to the content address, re-hashes the final file, re-checks the lease inside the write transaction and only then appends `artifact_inspections` (append-only triggers) and publishes metadata (`verification_source=workstation_signed_inspection`). Exact retries are idempotent; a reused inspection id with different content is `INSPECTION_REPLAY_CONFLICT`. Release creation additionally binds the inspected artifact to the same source commit, job and worker as its quality receipt. Unsigned JSON, client-asserted `verification`, forged/tampered signatures, changed bytes, stale fences/receipts, revoked workers, other principals and other projects are rejected (`tests/workstation-inspection.test.mjs`, production-mode HTTP+SQLite, synthetic bytes = policy evidence only). No Android SDK tool or inspector override exists on the server. Physical workstation upload of a real FLOW APK/AAB is NOT yet observed.

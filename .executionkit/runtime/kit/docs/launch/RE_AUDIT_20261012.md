## Material findings

### P0: destructive startup cleanup without ownership/exclusive agent proof

APKrelease agent/agent.mjs run() calls supervisor cleanup and recursively removes every work_root/job-UUID directory before the runner HostLock is acquired. There is no agent-wide exclusive startup lock or persisted ownership validation. Starting a manual instance while autostart is active can reap the other instance's build processes/workspace. Unknown UUID-named directories also qualify for deletion.

Reproduction used an isolated temporary folder and synthetic API/runner fixture: create an unregistered job-UUID directory containing a sentinel; invoke createAgent.run({once:true}); expected preservation=true, observed=false. No real application data/builds were touched. Result: FAIL. Preserve unknown paths, acquire the relevant lock before recovery, and prove process retirement before reclaiming known owned worktrees.

Retention of those old paths is correct for safe migration; it is not full canonical command integration.

Studio controls deliberately exclude enrollment/revocation, release approvals/promotions and rollback; the current surface is a monitor plus verify/debug/cancel/directives. Those exclusions protect current authority, but the originally requested unified release/agent manager is not complete. Quality/Visual/Test OS acceptance evidence is not fully wired into a single exact-source mobile release boundary.

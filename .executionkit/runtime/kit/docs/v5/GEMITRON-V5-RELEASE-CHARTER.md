## Ownership
ExecutionKit is GemiTron's portable **engineering execution arm**, independent CLI installed inside each consumer repo, respecting that repo's AGENTS.md/TODO.md, exact source SHA and its canonical Test/Audit/Visual and release facts. Keep **eleven executable systems in v5**: Execution, Agent, State, Content, SEO, Docs, Audit, Test, Launch, Visual and the bundled deterministic Decision OS. v4 compatibility retains its historical ten-system contract. Repository Intelligence, database/route integrity and caches remain cross-cutting fabrics, not more systems. GemiTron Studio renders engineering workspace/Creator/design and policy-bounded views; Official Antigravity remains first-party and owner-controlled, without an external provider fleet relay; Local Build Agent executes independently authorized typed native jobs, separate from Google identities; Launch holds single final release authority; GemiShield (planned) owns license/protection entitlements; FLOW owns client/finance/business project records only. No duplicated TODO/task state, Fleet leases, or separate deploy/publisher engines.

## Exactly what makes v5 a major release
**Launch OS v2** must stabilize within existing Launch OS as sole release controller for Web and mobile. Existing consolidated source includes Node service, SQLite migrations 001–006, signed gate and workstation artifact inspection, role-separated API, agent enrollment/fencing and Flutter updater SDK. v2 should complete source and API compatibility, approved web CWP vhost/site/DB/queue/scheduler release and rollback, bounded physical build jobs, artifact provenance, release digest and Test/Audit/Visual/accessibility acceptance, exact commit, expiry/revocation, independent approval, channels, gradual rollout, signed manifests, storage retention and off-host restore. Preserve old APKrelease client/updater URLs, signing trust, prior releases and history until real consumers accepted; legacy repo deletion requires *separate owner approval* after verified physical device/OTA and no dependencies. Owner expressly waives creation or preservation of legacy **Git repository** backups for repository deletion; deletion is irreversible. This does not waive production database/artifact recovery requirements for live release operations.

Android/Flutter builds, Gradle, APK/AAB/debug APK generation, Android SDK/emulator installations/downloads, Flutter mobile tests/bootstrap and Shorebird compilation are forbidden on **every VPS**, even if KVM/resources/root. Native workloads are strictly physical owner-enrolled Windows/macOS under Windows Job Objects/cgroups, quotas, local credentials/signing, real device receipts and agent reconnect/fence safeguards. Preserve installed app identity/cert/versionCode, data/SMS, PackageInstaller consent. Shorebird patch uses official eligible Dart-only source classification plus provider dry-run, baseline key, billing approval, official provider history and actual device restart; native changes/permissions/unsafe assets require a full build. Do not fabricate signing/quality/device/provider evidence.

**Decision OS** is official system 11 in v5, bundled locally from the preserved deterministic engine. No models, remote-daemon dependency or new task database. `GemiTron88/KB` owns reviewed generic engineering knowledge; automatic exact-commit/digest/schema/revision-checked updates apply atomically at TTL boundaries with a validated local fallback. Mandatory compiled DENY blocks; REVIEW and ALLOW never grant release authority or bypass Test/Audit/Visual/Launch. Typed schema v2 still rejects project names, paths, content and arbitrary signals. See `STANDARD_V5.md`.

**GemiShield** is future protection/licensing service. Kit may consume verified license policy when defined, but cannot issue paid licenses, alter customer finance, become a key vault or let entitlement logic bypass Launch. **GemiTron MCP** is a separate gateway composing typed approved Kit/Launch/Studio/typed local build/Shield actions, not a built-in Kit MCP daemon or generic arbitrary shell/provider CLI relay.

**Owner v5 release decision (2026-10-14):** VPS Staging is **not required** to publish standalone ExecutionKit v5. Retain older staging receipts as historical evidence only; never provision a new staging service/VPS or change production CWP permissions merely to release the Kit. Real production deployments still need exact candidate checks, signed authorization, backups, health and rollback; real Android acceptance still needs a physical workstation/device. ## Formal release gates
1. Published v4 exact-source regression floor, ten systems, native Agent OS, State recovery, Docs/SEO/Content/Visual V2/Audit/Test, DB/Route guards all remain operable; source and installed consumer compatibility tested.
2. Versioned v4→v5 CLI/AGENTS/installation/manifest/task/evidence/Launch API/SDK contract changes; migrations idempotent, rollback and pin to v4 possible, release notes explain breaking changes.
3. Launch OS v2 Node/Python/web/Studio API tests, signed lease/inspection/fraud/replay/role/idempotency negative tests, REST and SQLite backup/restore, resource budgets, independent operator approval and existing directly observed web-deployment/security/backup evidence; VPS Staging is not an independent release gate and no production success may be invented.
4. Workstation limits real OS readback, genuine release APK/AAB and identity evidence, physical Android install/update/rollback/SMS persistence, Shorebird optional actual provider receipt and billing if enabled.
5. Decision OS mandatory local deterministic engine's host class, privacy/schema/timeouts/outage, benchmarked latency/token budgets and hard-policy independence; no model subsystem or standalone service is permitted.
6. Studio, Fleet and representative Laravel+Flutter consumer acceptance by exact SHA; no duplicated project state; provider policy HOLD remains.
7. Owner approves signed candidate, version bump/official v5 tag only after required mandatory evidence; distinguish SOURCE-TESTED, CI, PHYSICAL and independently verified PRODUCTION. Retain STAGING as a label on historic test receipts only.
